## Overview

fabricOS is a multi-robot ground control and sensor analytics platform. The core insight is
architectural: the Hub ships as a **library** (`hub-core`) rather than an application, so a single
codebase drives three runtimes — a headless cloud binary, a Tauri desktop app, and Tauri mobile —
selected at build time through Cargo features.

## Key Features

- **One Hub, three runtimes**: cloud, desktop, and mobile builds compile from the same Rust core, eliminating the drift that usually creeps in between a ground station and its companion apps.
- **MAVLink telemetry pipeline**: real-time link handling over UDP, with a typed protocol crate as the single source of truth.
- **Type-safe boundary**: the TypeScript protocol package is generated from the Rust types via `ts-rs`, so the wire format cannot silently diverge from the frontend.
- **Built-in SITL**: ArduCopter software-in-the-loop is installed and supervised from inside the app, making the whole stack testable without hardware.
- **Sensor analytics**: ingestion and analysis of flight and sensor logs alongside live telemetry.

## Technologies Used

- **Rust** — protocol, hub core, MAVLink link, SITL manager
- **TypeScript / React** — web, desktop, and mobile frontends
- **Tauri** — desktop and mobile shells over the shared Rust core
- **Python** — analytics and tooling
- **Cargo + pnpm monorepo** — one workspace, many targets

## Outcome

fabricOS is the platform layer the rest of my robotics work sits on: a fleet operator gets the same
interface whether they are at a desk, in the field on a tablet, or watching from a browser.
